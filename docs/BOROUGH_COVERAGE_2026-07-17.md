### Freshness caveat

`public/data/pint_prices_app_dataset.json` rows have no `observedAt`/date field, so a per-venue or per-borough "freshest observation date" cannot be computed from the shipped data. Dated provenance exists only at the snapshot level in `public/data/price_updates/prices_YYYYMMDD.json` (and the drink/food equivalents). Any future per-observation freshness needs a dated field carried through the export pipeline.

## Ingestion pipeline (read before expanding)

The London slim index the map reads is built by a deterministic, no-network chain over one committed source of truth — `public/data/pint_prices_app_dataset.json`:

```
export:data (python, from data/*.csv)  ->  canonicalize:venues  ->  build:slim  ->  build:pubmaxxing-seed
```

- **`export:data`** (`scripts/export_app_dataset_json.py`) rebuilds the app dataset from the committed CSV lineages under `data/` and assigns `primary_borough` via the same point-in-polygon classifier as `lib/londonBoroughPoint.mjs`. No keys, no network.
- **`canonicalize:venues`** (`scripts/canonicalize_venue_dataset.mjs`) collapses duplicate physical pubs across lineages in place and writes `venue_id_aliases.json`. Idempotent, no network.
- **`build:slim`** (`scripts/build_slim_index.mjs`) groups rows by the FNV-1a stable venue id (mirrors `lib/venues.ts`), keeps the min numeric `price_gbp` as `cheapestPrice`, and stamps `borough` from `primary_borough`. **Coverage in this report is measured off this artifact.** No keys, no network. Confirmed reproducible: a full rebuild produced a byte-identical `venues_slim.json` (zero git diff).
- **Venue presence (unpriced pins)** enters only through curated, provenance-stamped gazetteer seeds merged by `scripts/merge_outer_london_gazetteer.mjs` (`data/outer_london_gazetteer_seed.json`, 66 Outer London pubs across Havering/Hillingdon/Redbridge/Barnet/Harrow) and `scripts/merge_london_chain_gazetteer.mjs` (`data/london_chain_gazetteer_seed.json`, 63 chain pubs). Every seed row carries `provenance: "sourced"` + a `source_note`; nothing is invented.

### Price-refresh sources & provenance rules

- **`refresh:prices`** (`scripts/refresh_prices.mjs`) reads the `data/price_sources.json` allowlist and refuses any URL not marked `first-party-official` / `open-data`. Its `fetchFromSource()` is a documented **stub returning `[]`** and the allowlist holds only `example-*` placeholders — so a run is a safe no-op that adds no rows.
- **`refresh:drink-prices`** (`scripts/refresh_drink_prices.mjs`) + the Firecrawl chain harvesters (`firecrawl_greene_king_prices.mjs`, `firecrawl_mbplc_prices.mjs`) target first-party chain drink menus (Greene King, Nicholson's, Wetherspoons). These require `FIRECRAWL_API_KEY` and live network access. **They feed `public/data/drink_price_updates/` — a separate runtime overlay read at venue-detail time — NOT the slim index's `cheapestPrice`.** `build_slim_index.mjs` reads no `price_updates` file, so running them does not change any number in this coverage table.
- **Hard governance (all refreshers):** every emitted price carries `{ source, observedAt }` (or `licence`), rows that can't be attributed to a specific venue are dropped (never guessed), no competitor price-aggregators, and output goes through a reviewed PR — never a push to main.

## Expansion status (this cycle)

Honest accounting of what could be run to raise coverage using the EXISTING scripts:

- **Gazetteer seeds — exhausted.** Both merges are already fully applied (`merge_london_chain_gazetteer` → 0 merged / 63 skipped). Re-running `merge_outer_london_gazetteer` merges 1 "new" row — but it is a **coordinate-drift duplicate** of *The Moon on the Hill – JD Wetherspoon* (Harrow), which already exists with canonical priced rows: the seed's coords (51.5795, -0.335) round differently from the already-merged copy (51.5794, -0.3342), dodging the 4-decimal dedup key. This was **not committed** (it would double a pin). Filed as a seed/dedup finding for a later cycle.
- **`refresh:prices` — nothing to run.** Stub + placeholder allowlist; produces no rows.
- **Firecrawl drink harvesters — out of scope for this metric.** `FIRECRAWL_API_KEY` is available, but the output is a drink-menu overlay that does not touch slim `cheapestPrice`/borough coverage, so running it cannot improve this table. Left for the drinks-enrichment lane, not the coverage lane.
- **No keyless London venue-ingestion path exists.** `fetch:city-pubs` (Overpass/OSM, keyless) is scoped to the non-London Wave-2 cities (Manchester, Liverpool, …), not Greater London. Adding Outer-London pub *presence* at scale would need a new curated seed or a new ingestion script — deliberately out of scope for "expand via existing scripts".

**Net:** the deliverable this cycle is the honest coverage table above; no data rows were added (every honest lever is either exhausted, stubbed, or off-metric). The clearest next-cycle wins are Outer-London **venue presence** in the worst-10 boroughs (curated sourced seed rows, unpriced pins acceptable) and adding a dated `observedAt` to the export so freshness becomes measurable.
