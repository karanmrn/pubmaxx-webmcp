## 4. Blocker A: RESOLVED on main by #740, production still needs a redeploy

Karan promoted `f508749f` to production at 04:23. That promotion
(`dpl_FD2VD8JC6MAvYoT1bH6YRAo8ecnQ`) is state **ERROR**. The preview it promoted
from built READY, so the code is fine and the production build is what failed.
The alias never moved, so production still serves the previous READY build.

`npm run ci` runs inside the Vercel production build, and three tests fail there
while passing in GitHub CI on identical source:

```
__tests__/authProviderAvailability.test.ts   "does not request Clerk environment
                                              when its publishable key is absent"
__tests__/clerkProxyCsp.test.ts              "fails closed on an undefined value"
__tests__/clerkProxyCsp.test.ts              "leaves the policy unchanged while
                                              no Clerk key is configured"
```

**Root cause.** All three assert the no-Clerk-key path. `isClerkConfigured()`
and `clerkFrontendApiOrigin()` default their argument to
`readClerkPublishableKey()`, which reads `process.env` directly, and the tests
never pinned that variable. The Vercel production environment carries a Clerk
publishable key; GitHub CI does not.

**The fix is PR #740, merged as `3ebacd34`** - one hunk in `vitest.setup.ts`:

```ts
delete process.env.NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY;
delete process.env.CLERK_SECRET_KEY;
```

That file already owns exactly this job for `VERCEL`, `SUPABASE_URL`,
`SUPABASE_SERVICE_ROLE_KEY`, and `NEXT_PUBLIC_DEMO_CONTENT`, so Clerk belongs
beside them rather than in a second owner inside the test files.

Two agents diagnosed this independently and got the same answer. Opus 5
reproduced it locally - reverting to the original files and running with a
synthetic key gave `3 failed | 50 passed (53)`, matching Vercel exactly - and
Codex's PR body records the same RED-to-GREEN proof. Opus 5's own per-file fix
was reverted in favour of #740; a copy survives in the session scratchpad if the
per-file framing is ever wanted.

**Do not add a Clerk key to CI and do not weaken an assertion.** Either would
make the suite agree with whatever environment happens to run it, which is the
defect itself.
